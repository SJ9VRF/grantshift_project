GrantShiftStress-testing whether personalized AI agents keep authority scoped, current, provenance-bound, and revocable.

Personalization can persist while permission changes. GrantShift separates what a user tends to want from what the agent is authorized to do now, then stress-tests that boundary under revocation, expiry, replay, delegation, concurrency, and scope changes.

01 · Problem

A model can know what you want and still act without valid authority.

Preference is persistent context. Authorization is a changing, action-specific capability. Treating both as the same state creates stale-permission failures that can look like successful personalization.

Failure mode 01

Revocation is not forgetting

The user can keep the same preference while withdrawing permission for a specific task, resource, or principal.

Failure mode 02

“Granted” is underspecified

A label omits request identity, resource, revision, nonce, expiry, delegation ancestry, and revocation history.

Failure mode 03

Task success can hide a boundary violation

An agent may complete the task while using a capability that should no longer be valid.

02 · Core idea

Represent authority as a lifecycle-aware capability, not a memory label.

GrantShift binds each actionable grant to principal, request, resource, revision, nonce, expiry, and delegation lineage. The action gate revalidates that capability at decision time instead of trusting the latest authorization-like text in memory.

Novelty boundary. The contribution is not the generic claim that “agents need permissions.” The benchmark contribution is the controlled, matched testing of dynamic authorization transitions while preference evidence is held fixed, plus scope/provenance/lifecycle adversaries and mutation sensitivity that independently exercise the validity invariants.

Preference informs behavior. Capability state gates action.

05 · Experiments

From easy benchmark wins to a challenge that could break the method.

The benchmark was repeatedly strengthened after shortcuts or blind spots were found. That evolution is preserved in the experiment journal rather than hidden behind the final result.

Task construction

Six domains, three preference histories, matched authorization counterfactuals, multi-turn trajectories, paraphrase and OOD stress.

Baselines

Latest authorization label, flat provenance matching, and lifecycle-aware capability ledger.

Ablations / falsification

Delete expiry, nonce revocation, parent revocation, request, principal, resource, or revision checks one at a time.

07 · Failure analysis

The failures that changed the project.

Benchmark

Surface shortcut

Canonical cases looked strong, but paraphrase performance collapsed.

Diagnosis

The model/policy could key off presentation instead of authorization semantics.

Change

Added held-out paraphrases, surface augmentation and negative controls.

Policy

Delayed confirmation bug

The static policy could repeatedly ASK instead of consuming a fresh confirmation correctly.

Diagnosis

Authorization needed task revision and request identity, not conversational recency.

Change

Moved from label state to scope-bound capability state.

Our method

Over-permissive delegation recovery

A stale child grant could be replayed after its parent authority was revoked.

Diagnosis

Flat token validity was insufficient; ancestry had to be traversed.

Change

Added parent-revocation semantics and regression cases.

Evaluation

Mutation blind spots

Several broken invariants initially still scored 100%.

Diagnosis

The benchmark did not independently isolate every intended validity property.

Change

Added direct isolation families until every targeted mutant failed.

10 · Safety & limits

The system is designed to refuse stale authority—not to claim deployment safety.

Irreversible actions

Low-recoverability or ambiguous actions should require fresh, correctly scoped authority.

Permission boundaries

Unknown principal, stale revision, conflicting grants, replay, expiry, or invalid ancestry should block execution.

Human escalation

Ambiguity or high stakes should route to ASK / DEFER / human confirmation instead of autonomous action.

Not yet established: frontier-model generalization, human normative agreement, real-browser/tool reliability, production security, adversarial-user robustness, or post-training gains.
11 · Inside the research process

The scientific story is intentionally not “idea → perfect result.”

The evidence layer keeps the weird results, broken assumptions, method bugs, benchmark blind spots, and design decisions that produced the final release.

01
Canonical benchmark looked strong.~98.7% on structured/canonical cases.
02
Held-out paraphrases collapsed.~52.8% exposed a surface shortcut rather than semantic robustness.
03
Surface augmentation repaired that failure.Paraphrase performance returned to ~99%, but this created a new question: was the transition benchmark itself too easy?
04
Scope and provenance challenges broke the shortcut.Latest-label tracking no longer sufficed once the same “grant” had to be bound to the correct task state.
05
The capability ledger fixed one class—and introduced its own bug.Delegation ancestry semantics had to be corrected after a stale child grant remained too permissive.
06
Mutation testing attacked the benchmark itself.Five missing isolation tests were discovered and added before the release gate could be considered credible.
07
Final gate: all seven targeted invariant deletions must fail.The released challenge now detects every targeted mutation; external-model evidence remains a separate next step.
